## 1. Erasure asks for consent again before anything leaves the phone

### What exists

`src/features/friends/ProfileSheet.tsx`: `erase()` awaits `deleteMyData()` and, on success, calls
`resetSocialIdentity()` and sets the status line to "Deleted. Your phone's copy stays."
`src/state/backend.ts`: `deleteMyData()` runs the `delete_my_data` RPC and signs the session out.
`src/state/store.ts`: `resetSocialIdentity()` mints a new local id and code and keeps the name.
`src/state/sync.ts`: `mode()` returns `'off'` while `enteredCruise` is false (workstream B), so
nothing signs in or publishes until the entry screen's Done; `ensureSession()` on the next round trip
is what mints a replacement anonymous user today, measured on 10 September and recorded in
`CLAUDE.md` under Seed. `src/app/App.tsx`: renders `Entry` whenever `enteredCruise` is false.
`src/features/privacy/PrivacySheet.tsx`: the "Deleting it" paragraph.

### Behaviour

- Tapping Delete my data twice, online: the server rows go (unchanged), the session is signed out
  (unchanged), the local identity is reset (unchanged), **and `enteredCruise` becomes false**, so
  `App` shows the entry screen with the name field prefilled from the kept profile name. No sync
  runs until Done is tapped there. The status line "Deleted. Your phone's copy stays." is never
  seen because the sheet unmounts; that is acceptable, the entry screen is the confirmation, and
  its consent line says exactly what Done will do. Do not add a toast.
- Offline, or the RPC fails: unchanged ("Could not delete your data. Try again when you are
  online."), and `enteredCruise` is not touched, because nothing was erased.
- The "Deleting it" paragraph in the privacy note gains one sentence at its end, verbatim:
  "The app then asks again before anything leaves this phone."
- Implementation: extend `resetSocialIdentity()` to also set `enteredCruise: false`, with a comment
  saying why (a stranger has not consented), after grepping every caller to confirm `erase()` is
  the only one; if another caller exists that must not re-ask, add a separate store action
  `forgetConsent()` and call both from `erase()` instead. Say which in the commit.
- `CLAUDE.md` Seed: the bold "Tap Delete my data on a page loaded with `?nosync`" paragraph is
  rewritten to say the trap is closed and why, merged in place, nothing else touched.

### Verification

One live-backend check is allowed in this pass and only this one, because the claim cannot be
proven any other way: headless through `tools/qa/cdp.mjs`, fresh context, a fetch tap installed
before navigation, load `/?seed` with NO nosync so sync is live, wait for the seed's anonymous
signup and publish, capture the uid and code, open Crew, Your details, tap Delete my data twice,
then assert: `delete_my_data` and `auth/v1/logout` fired, the entry screen is on screen
(`.entry-done` present), and **zero** `auth/v1/signup` and zero `profiles` upserts for ten
seconds after. Report the uid and code for the purge ledger; the row is deleted by the run itself.
Then, on that same context, tap Done and assert sync resumes (a signup and a publish within three
seconds), then Delete my data again on a `?nosync` load to leave the backend clean, and report
that second uid too. Shots: `polish-erase-entry` (the entry screen after erasure, name prefilled).

## 2. A disabled `.btn` reads as disabled

### What exists

`src/styles/base.css` `.btn:disabled` falls to the plain surface, which a plain `.btn` already has,
so on the Profile sheet's offline state "Keep it with Google" (disabled) and "Delete my data"
(enabled) are visually identical (`c-profile-offline.png`, 10 September). `docs/DESIGN.md` States
says every control ships default, pressed, focus-visible and disabled.

### Behaviour

- `.btn:disabled` (and `.btn[aria-disabled="true"]` if the codebase uses it; grep) uses existing
  tokens only: text `--ink-2`, no fill, `--line` border, `cursor: default`, no press tint. It must
  differ from an enabled plain `.btn` in a computed-style eval, not only to the eye. No opacity
  rule (opacity dims the glass film beneath). Register the state in `DESIGN.md` States as one line
  if it is not already there; do not add a new token or radius.
- Sweep: every `.btn` that can be disabled (grep `disabled=` and `disabled` on buttons) keeps
  working; `GlassButton`'s own disabled handling, if any, is checked for agreement, and the one
  rule wins over any local override.

### Verification

Run `tools/qa/shot.mjs` with label `polish-disabled`, route
`social?qa=account:guest,sync:held&nosync`, `--click "[aria-label='Your details']" --after 3000`,
and an `--eval` that maps every `.friends-sheet .btn` to its trimmed text, `disabled` flag and
computed `color`, `backgroundColor` and `borderColor`. The disabled button must differ from the
enabled one in at least one of the three computed values, and the PNG must show it reading as
inert without a pill, a dot, a rule or an emoji.

## 3. The privacy note replaces the Profile sheet rather than stacking on it

### What exists

`ProfileSheet.tsx` renders the privacy row (`button.row.pressable.privacy-open`) and, when tapped,
mounts `PrivacySheet` from local state while the Profile sheet stays mounted: two `.sheet` nodes,
the second covering the first exactly (both cap at 88svh). `docs/DESIGN.md` Material forbids a
sheet over a sheet. The house pattern for a sheet that leads to another is replacement:
`VenueSheet` returns `<DrinkSheet …/>` when a drink is open, and BYO's `VenueForm` replaces
`VenueSheet` the same way.

### Behaviour

- Tapping the privacy row inside Your details closes the Profile sheet's content and renders the
  privacy note in its place, in the same `Sheet`: one `.sheet` node at all times.
- Closing the privacy note (drag, scrim, Escape, the close control) returns to Your details, not to
  the page: the guest opened it from there. So `PrivacySheet`'s `onClose` in this path sets the
  local flag back rather than closing the outer sheet.
- The entry screen's privacy row is unchanged (it opens the note over the page, which is one sheet).
- `Sheet.tsx` is not touched. This is a `ProfileSheet.tsx` change only, plus one sentence in
  `DESIGN.md`'s Sheets section if the replacement rule is not already written there.

### Verification

Run `tools/qa/shot.mjs` with label `polish-privacy`, route `social?nosync`,
`--click ".social-me" --click2 ".privacy-open" --after 3000`, and an `--eval` returning the count of
`.sheet` nodes and the text of `.sheet-title`. It must print one sheet titled "Privacy note". A
second run that also dispatches Escape after the second click must print one sheet titled "Your
details". `node tools/qa/gestures.mjs` must still pass every case.
